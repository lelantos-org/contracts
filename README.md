# Lelantos Contracts

Solidity contracts for a Multi-Asset Shielded Pool (MASP), built with [Foundry](https://book.getfoundry.sh/).

## Architecture

| Contract | Role |
| --- | --- |
| `MASP.sol` | Pool entry points. Inherits `CommitmentTree`, `AssetRegistry`, `NullifierSet`, `FeeConfig`. |
| `CommitmentTree.sol` | Lazy-root quaternary tree: 64-slot known-root ring buffer and `committedCount`. |
| `AssetRegistry.sol` | Owner-managed asset id to (ERC-20, scale) mapping. Add-only; assets can be disabled but not removed. |
| `NullifierSet.sol` | Packed-bitmap spent-nullifier set. |
| `FeeConfig.sol` | Fee bps, treasury, and per-token accrual drained by `sweep`. |
| `libs/PubInputs.sol` | Public-input structs and Fiat-Shamir compression to `(y, z)`. |
| `libs/AuxValidation.sol` | Bounds and curve checks on per-output FMD payloads. |
| `SnarkCompression.sol` | Horner evaluation over the coefficient vector. |
| `BabyJubJub.sol` | On-curve and prime-order-subgroup checks. |
| `swap/SwapWrapper.sol` | Atomic unshield to swap to re-shield across a MASP pair. |
| `swap/UniV3Adapter.sol` | Uniswap SwapRouter02 adapter for `SwapWrapper`. |

Entry points:

- `submitIntent` / `submitIntentAuthorized` / `submitIntentNative` — escrow funds; no SNARK verified at submit.
- `flushBatch` — insert up to `MAX_N_BATCH = 8` escrowed intents under one `tree_update_batch` proof.
- `cancelIntent` — refund the digest-bound payer after `cancelDelay`.
- `transfer` / `withdraw` / `withdrawNative` — spend operations verifying `transact_2x2` and `tree_update_batch` with `actualCount == 1`.

Spend operations verify two Groth16 proofs: the transaction proof, and a tree-update proof that advances the Merkle root. Leaf insertion is proven rather than computed on-chain.

Public-input layouts in `libs/PubInputs.sol` must match the circuit-side PolyEval coefficient order in `../circuits`. Both structs are fully static, so their calldata block is word-for-word identical to the coefficient vector; `test/PubInputs.t.sol` pins that equivalence against independent reference implementations.

## Setup

Requires [Foundry](https://book.getfoundry.sh/) and Solidity `^0.8.30`.

```bash
git clone <repo>
cd contracts
forge install
```

## Development

Commands are wrapped in the [`justfile`](justfile); run `just` to list them.

```bash
just build          # forge build
just test           # forge test -vvv
just test-fuzz      # heavy fuzz + invariant sweep (nightly profile)
just fmt            # forge fmt
just size           # EIP-170 size check under the deploy profile
just snapshot       # forge snapshot
just ci             # version + build + test + fmt-check + size
```

Build profiles (see `foundry.toml`): `default` (via-IR, `optimizer_runs = 1_000_000`), `fast` (quick local iteration), `deploy` (`optimizer_runs = 10_000`, keeps MASP under the EIP-170 limit), `fuzz` (nightly depth), `smt` (opt-in model checker).

## Tests & Fixtures

Test vectors live in [`test/fixtures/`](test/fixtures/) (see its [README](test/fixtures/README.md)):

- `asset_registry.json` — asset generators for MASP deploy
- `proof_deposit_batch_n1.json` — sample batched tree-update proof
- `proof_transfer.json` — sample transfer proof
- `tree.json` / `empty_root.json` — Merkle tree expected roots

Fixtures are generated by the circuits crate at `../circuits`. Regenerate with `just gen-fixtures` whenever hash parameters, tree depth, or the generator set change. Proof fixtures require `../circuits/build/tree_update_batch_final.zkey` (build with `cd ../circuits && just rebuild-batch`); override the location with `just --set CIRCUITS_BUILD /abs/path gen-fixtures`.

Most tests mock Groth16 verification via `vm.mockCall` to isolate contract logic from circuit correctness. Tests exercising real proofs against the bundled fixtures are named `*RealSnark*`.

## Deployment

Four deploy scripts, split into MASP-core and swap-stack pairs. Mainnet deploys run under `FOUNDRY_PROFILE=deploy`.

| Script | Target |
| --- | --- |
| `script/DeployTest.s.sol` | anvil MASP core |
| `script/DeployTestSwap.s.sol` | anvil swap stack |
| `script/Deploy.s.sol` | mainnet MASP core |
| `script/DeploySwap.s.sol` | mainnet swap stack |

Local:

```bash
just anvil                # anvil --chain-id 31337
just deploy-anvil         # DeployTest
just deploy-test-swap     # DeployTestSwap (after deploy-anvil)
```

Mainnet (no `just` recipe; invoke `forge script` directly):

```bash
FOUNDRY_PROFILE=deploy forge script script/Deploy.s.sol:Deploy \
  --rpc-url "$RPC" --ledger --broadcast
FOUNDRY_PROFILE=deploy forge script script/DeploySwap.s.sol:DeploySwap \
  --rpc-url "$RPC" --ledger --broadcast
```

Omit `--broadcast` to simulate.

- `DeployTest` deploys `Verifier`, `TreeUpdateBatchVerifier`, `MASP`, Permit2 (etched at its canonical address), `MockWETH9`, and `MockERC20`s seeded from `asset_registry.json`, signing with anvil dev key #0.
- `DeployTestSwap` requires `MASP`, `PERMIT2`, `TOKEN_1`, `TOKEN_2`, `TOKEN_3` in the environment; `MASP_OWNER` defaults to `tx.origin` and `MASP_TREASURY` to `0x…dEaD`. Take the addresses from the `deploy-anvil` output.
- `Deploy` reads `script/config/mainnet.json` (override with `MAINNET_CONFIG`); `DeploySwap` reads `script/config/mainnet.swap.json` (override with `SWAP_CONFIG`). Neither default file is committed — copy the corresponding `*.example.json`, which documents the schema. Arbitrum configs are committed alongside.

Shared logic lives in `script/base/BaseDeploy.s.sol` and `script/base/BaseSwapDeploy.s.sol`.

## Gas

Both Groth16 verifiers cost 195 026 per `verifyProof` call regardless of logical public-input count, since PolyEval compresses the public inputs to `(y, z)` before the pairing.

End-to-end with real proofs (`test_transferRealSnark_succeeds`):

| Component | Gas |
| --- | --- |
| `MASP.transfer` total | 524 457 |
| ├ `Groth16Verifier.verifyProof` | 195 026 |
| ├ `TreeUpdateBatchGroth16Verifier.verifyProof` | 195 026 |
| └ contract logic, storage, events | 139 405 |

Aggregates from `forge test --gas-report` (default profile). Verification is mocked in most tests, so these exclude the 195 026 per proof above. `Min` is generally an early-revert guard path and `Max` the fullest success path. Fuzz and invariant runs contribute calls, so exact values shift between runs:

| Function | Min | Avg | Max | Calls |
| --- | --- | --- | --- | --- |
| `submitIntent` | 30 676 | 125 072 | 171 434 | 16 424 |
| `submitIntentAuthorized` | 41 771 | 88 425 | 145 897 | 8 |
| `submitIntentNative` | 28 910 | 60 871 | 159 047 | 11 |
| `flushBatch` | 34 287 | 135 790 | 187 047 | 4 050 |
| `cancelIntent` | 25 539 | 51 180 | 66 888 | 9 614 |
| `transfer` | 43 512 | 54 234 | 202 653 | 800 |
| `withdraw` | 43 634 | 164 706 | 264 774 | 518 |
| `withdrawNative` | 43 261 | 162 760 | 289 730 | 4 |
| `sweep` | 24 226 | 27 868 | 56 898 | 16 488 |
| `SwapWrapper.swap` | 45 607 | 54 848 | 289 338 | 275 |

Notes:

- `submitIntent` covers the per-deposit path: Permit2 `permitWitnessTransferFrom`, aux validation, a single-slot escrow-digest write, and the `IntentEscrowed` log carrying both encrypted note payloads. No proof verification and no fee-map writes on this leg.
- `flushBatch` amortizes one batched tree-update proof and the Merkle root advance across up to `MAX_N_BATCH` intents. Each intent's submit-time digest is rebuilt from calldata (`tpi` plus `IntentMeta`) and compared against a single storage slot. Fees accrue once per unique token in the batch.
- `cancelIntent` refunds escrow after `cancelDelay`, checking the caller-supplied digest preimage against `escrowed[id]`. All preimage fields come from the `IntentEscrowed` event; `submittedAt` is that event's block number.
- `withdrawNative` adds the unwrap and raw-native send to the `withdraw` path: `IWrappedNative.withdraw(net)` burns the pool's wrapped balance, `receive()` accepts the returned native, and the recipient is paid by low-level call. The fee stays wrapped and is claimable through `sweep`.
- Fee accounting is off the deposit path: `submitIntent` locks `inAmt + fee` in escrow without touching any fee map, `flushBatch` accrues each intent's submit-time fee into `accruedFee[token]`, `cancelIntent` refunds principal and fee from balance, and `sweep(token)` drains the accrued balance to the treasury. Escrowed funds are never part of `accruedFee`.

Deployed sizes under the deploy profile (EIP-170 limit 24 576 B):

| Contract | Runtime (B) | Margin (B) |
| --- | --- | --- |
| `MASP` | 20 317 | 4 259 |
| `SwapWrapper` | 7 504 | 17 072 |
| `UniV3Adapter` | 2 073 | 22 503 |
| `Groth16Verifier` | 1 463 | 23 113 |
| `TreeUpdateBatchGroth16Verifier` | 1 463 | 23 113 |

Check with `just size` or `just build-sizes`.

## Dependencies

`@openzeppelin/contracts`, `forge-std`, `poseidon-solidity`, `permit2`.

For local deploys, Permit2 is etched at its canonical address (`0x000000000022D473030F116dDEE9F6B43aC78BA3`) via the precompiled-bytecode `DeployPermit2` helper. This avoids compiling `Permit2.sol`, which is pinned to `=0.8.17`, against project sources at `^0.8.30`.
